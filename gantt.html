Simulation considerations
Time. Labour is tracked in continuous real seconds; the calendar runs in day ticks of 40s. An action may straddle a tick edge — the worker never waits for one. Growth is tick based, not time based: a spot ripens on a tick boundary a fixed number of day ticks after the tick its sow finished in, so the sub-tick offset of the sow is discarded and the ripe edge always lands on a boundary.

The spot cycle. EMPTY → plow → PLOWED → sow → GROWING → (grow time) → RIPE → harvest → EMPTY. Growth is always the full grow time in day ticks on the game clock; only the wall-clock wait varies, by less than one tick, with the sow offset.

Workers. Each carries its own clock, so several work different spots at the same time. Task priority is harvest → sow → plow, breaking ties by the closest cell in Euclidean distance. Walking is charged whenever a worker moves to another cell.

Calendar. A year is 365 days. Days 271–365 are winter: no labour, but growth continues, so autumn crops ripen and wait for spring. Winter is excluded from all percentages and idle reporting.

Field layout. A near-square grid filled row-first from the bottom-left: the index runs left to right along each row, then the next row up. No snake fill. Walking is between cell centres, never by spot index.

Datamined values. See the Datamined game values section below.

Not modelled: worker pathfinding or collisions, tool quality, weather, and any yield multiplier. Two workers may briefly converge on the same square since there is no collision model.
